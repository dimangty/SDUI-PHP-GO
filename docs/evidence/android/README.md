- Login/Registration are captured with empty inputs before credential entry.
- PIN pictures show only actual two/three entered-dot counts and public keypad
  keys. The generated six-digit PIN stays local; both setup and login retain the

- Profile/editor show only the UI-created synthetic account and real returned
  address. The email identifier and random password use independent randomness;
  exported account identifiers cannot derive credentials.
- Editor captures wait for the loaded actual name, check readonly native email
  actions and absence of bottom/ordinary host navigation, and leave via Back

  disabled with the honest unavailable caption; notifications remain unsupported.

  never changed for screenshots. Cart capture retains real structured field data,

- No password/PIN sequence/token, Chrome/provider capability URI, browser capture
