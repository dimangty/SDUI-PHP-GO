## PHP 8.5 compatibility work actually executed

- Replace no-op `curl_close()` / `imagedestroy()` with object-reference release.
  With diagnostics promoted to exceptions, PHP 8.5 reproduced both a broken HTTP
  success and cleanup masking the real response-limit failure, plus failed avatar
  normalization. New regression suite **3 RED → 3 GREEN**, registered in Composer
  and complete native suites; no warning suppression was added.
- Use `libpq-dev` rather than server-extension `postgresql-dev`. PDO needs client
  headers, not the server's LLVM development graph. Actual native builds, eager
  shared-library loading and libpq TLS tests pass; runtime pruning remains checked.
- PHP 8.5 has built-in OPcache. The gate checks required shared extension identities
  and actual OPcache loading rather than incorrectly requiring six `.so` files.
- Quiet successful entrypoint preflight preserves Composer JSON and machine stdout;
  failure stderr/nonzero behavior remains enforced. Existing runtime gate reproduced
  three stdout failures and then passed **5/5**.
- Native Argon2id, legacy PIN/biometric formats, PostgreSQL races/faults, FPM/FastCGI,
  scheduler, shutdown/restart and live PHP→Go flows passed on PHP 8.5. No token/
  password format or client-flow change was bundled with this runtime upgrade.
